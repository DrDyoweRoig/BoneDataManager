# Bone Data Manager — Plan 3: Android app Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** The same Flutter app runs on Android phones as a cloud-only data-entry client: sign in, open cloud databases, browse/search entries as cards, add/edit/delete (online only, by role), and share an Excel export.

**Architecture:** One codebase. A single `isMobile` switch (Android/iOS, overridable in tests) decides what the shell shows. Mobile reuses `LocalStore` as a private read cache and `SyncEngine` for pulling, but the engine runs with `allowOffline: false`: every write first checks the server is reachable and otherwise fails with `NeedsConnection`; no number blocks are reserved. Workspace swaps the wide table for cards; Home shows only the cloud list.

**Tech Stack:** Plans 1–2 stack + Android SDK (Android Studio), `share_plus` (share the exported .xlsx).

**Spec:** `docs/superpowers/specs/2026-10-23-bone-database-design.md` (§9, §10, §17)

## Global Constraints

- UI text in English. Offline banner: `You're offline. You can browse, but saving needs a connection.` Save error: `You're offline. Saving needs a connection.`
- Mobile never creates databases, edits structure/members, moves to cloud, makes backups or keeps a live Excel file; it has no local-only databases.
- Mobile never reserves or uses offline number blocks.
- Desktop behaviour must not change (all existing tests stay green).
- Release APK built with `--dart-define-from-file=cloud_config.json`; Android needs the INTERNET permission in the main manifest.
- Agent does not accept Android SDK licences or install software without the user's permission.

## Review Focus

1. Phone loses connection between opening the form and pressing Save → `NeedsConnection` message, nothing half-saved, no pending row left behind. Test in Task 1.
2. Viewer on mobile → no New entry, cards not tappable for edit. Test in Task 4.
3. Signed out on mobile → only a sign-in prompt, never the desktop Create/Open buttons. Test in Task 3.
4. A desktop that edits offline and then syncs still works exactly as in Plan 2 (`allowOffline: true` default). Existing sync tests.
5. Long layer values / many layers on a narrow screen → card text ellipsizes, no overflow errors. Test in Task 4.

### Task 1: Online-only writes in SyncEngine

**Files:** Modify `lib/cloud/sync_engine.dart`; Test `test/cloud/sync_engine_test.dart`

**Interfaces — Produces:**
- `class NeedsConnection implements Exception` with `toString()` = `You're offline. Saving needs a connection.`
- `SyncEngine(..., {bool allowOffline = true})`. When `false`: `createEntries`, `updateEntry`, `deleteEntry` first call `api.fetchDefinition(db)` as a reachability check; on `CloudOffline` → mark offline (event `WentOffline`) and throw `NeedsConnection` without touching the store. `updateEntry`/`deleteEntry` then write locally and `await syncNow()` (not fire-and-forget) so the change is uploaded before returning; `createEntries` never falls back to the block. `_round` skips block reservation.

- [ ] **Step 1: Failing tests:** mobile engine offline → `createEntries` throws `NeedsConnection`, store empty, server empty (Review Focus 1); offline → `updateEntry` throws, entry unchanged and not pending; online edit returns with server already updated; mobile engine never reserves a block (`store.block == null`, `server.blocks` empty).
- [ ] **Steps 2–5:** FAIL → implement → PASS (whole suite) → commit `feat: online-only writes for mobile`.
