# Bone Data Manager — Plan 2: Cloud (Supabase) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Share databases between computers through Supabase: accounts, roles, live sync, offline work with reserved ID blocks, conflict resolution and "Move to cloud" — on top of the Plan 1 desktop app.

**Architecture:** The desktop UI keeps talking to the local SQLite copy (`LocalStore`). A `SyncEngine` sits between the UI and the cloud: it creates entries through the server when online (server assigns numbers), from a reserved block when offline, queues local changes as *pending*, pushes them with optimistic versioning, and pulls remote changes (Realtime + periodic). All cloud calls go through a `CloudApi` interface so the engine is unit-tested against an in-memory fake; `SupabaseCloudApi` is a thin adapter. Server rules (roles, numbering) live in Postgres: Row Level Security + `security definer` RPC functions.

**Tech Stack:** Plan 1 stack + `supabase_flutter`, `connectivity_plus` (hint only), Postgres SQL (Supabase).

**Spec:** `docs/superpowers/specs/2026-10-23-bone-database-design.md` (§5, §6, §9, §10, §11, §16)

## Global Constraints

- UI text in English. Toasts verbatim from spec §10:
  - offline: `You're offline. New entries will use this device's reserved IDs, so numbering may have gaps. Changes will sync automatically when you're back online.`
  - back online: `Back online — N entries synced.`
- The app ships only the Supabase **URL** and **anon/publishable key**, read from `--dart-define-from-file=cloud_config.json` (git-ignored; `cloud_config.example.json` committed). Never the service_role key.
- Permissions are enforced on the server (RLS + RPC role checks), not only hidden in the UI.
- Roles: `owner` (structure, members, entries), `editor` (entries, export), `viewer` (read, export).
- Ref IDs are unique per database and never reused. Online numbers come from the server counter; offline numbers from this device's reserved block of **50**, refilled when half used.
- Local databases keep working with no account. Cloud databases on desktop always have a local SQLite copy in a folder the user picks; live Excel and backups work as in Plan 1.
- Member emails compare case-insensitively.
- Creating real accounts on the user's Supabase project is done by the user, not the agent.

## Review Focus

1. Offline with the reserved block used up → creating entries fails with `No reserved numbers left on this computer. Connect to the internet to add more entries.`, nothing half-saved. Test in Task 3.
2. The same entry edited on two computers (one offline) → second push gets a conflict; the conflict dialog lets the user keep either version; nothing silently overwritten. Tests in Tasks 3 and 9.
3. App closed with pending changes → they survive restart and push on next open. Test in Task 3.
4. A viewer (or a non-member) calling the API directly → rejected by the server. Manual SQL check in Task 1.
5. "Move to cloud" run twice or interrupted halfway → no duplicate database or entries; rerun completes it. Test in Task 8.

### Task 1: Server schema, RLS and RPCs

**Files:** Create `supabase/migrations/001_init.sql`, `supabase/checks/role_checks.sql`

**Tables** (all `id uuid`, timestamps `timestamptz default now()`):
- `databases(id pk, name, prefix, digits int, next_number int, selected_elements jsonb, layers jsonb, created_by uuid, created_at, updated_at)`
- `members(database_id fk, email text, user_id uuid null, role text check in ('owner','editor','viewer'), primary key(database_id, email))` — `email` stored lower-case.
- `entries(id pk, database_id fk, number int, ref_id text, element_id, dentition, tooth_type, jaw, side text null, "values" jsonb, created_by, created_at, modified_by, modified_at, version int, deleted bool, updated_at timestamptz default now(), unique(database_id, number), unique(database_id, ref_id))`; index `(database_id, updated_at)`.
- `id_blocks(database_id, device_id text, start_number int, end_number int, primary key(database_id, device_id, start_number))`

**Helper:** `my_role(db uuid) returns text` (`security definer`, `stable`): role where `members.database_id = db and (user_id = auth.uid() or email = lower(auth.jwt()->>'email'))`.

**RLS:** enable on all four tables.
- `databases`, `members`, `entries`: `select` when `my_role(database_id) is not null`.
- `members`: `insert/update/delete` when `my_role(database_id) = 'owner'`.
- No direct `insert/update` on `databases`, `entries`, `id_blocks` — RPCs only.

**RPCs** (`security definer`, `set search_path = public`, each starts with a role check that raises `insufficient_privilege`):
- `create_database(def jsonb, rows jsonb default '[]') returns void` — any signed-in user; inserts `databases` row (id from `def`), owner member row with caller's email + uid, and `rows` keeping their numbers; `next_number = greatest(def.next_number, max(number)+1)`. **Idempotent:** if the id already exists and caller is its owner, upsert missing entries only (Review Focus 5).
- `update_definition(db uuid, def jsonb)` — owner; updates name/prefix/digits/selected_elements/layers; never `next_number`.
- `create_entries(db uuid, drafts jsonb) returns setof entries` — editor/owner; `update databases set next_number = next_number + n ... returning` to take n numbers atomically; formats `ref_id` = prefix + lpad(number, digits) (wider numbers kept whole).
- `reserve_block(db uuid, device text, size int) returns table(start_number int, end_number int)` — editor/owner; takes `size` numbers from the counter, records in `id_blocks`.
- `push_entry(db uuid, e jsonb, base_version int) returns jsonb` — editor/owner. New id: insert (number must lie in one of caller's device blocks for `db`, else raise). Existing id: `update ... where version = base_version` setting `version = version + 1`, `updated_at = now()`; returns `{"status":"ok","version":v}` or `{"status":"conflict","row":<server row>}`.

**Realtime:** `alter publication supabase_realtime add table entries, databases;`

- [ ] **Step 1:** write the migration. **Step 2 (user):** paste it in Supabase SQL Editor → Run → "Success". **Step 3 (user):** create two test accounts in the app's project (Authentication → Users → Add user): `owner-test@…`, `viewer-test@…`.

### Task 2: Local schema v2 and EntryWriter

**Files:** Modify `lib/data/local_db.dart`, `lib/data/local_store.dart`; Create `lib/entries/entry_writer.dart`; Test `test/data/local_store_sync_test.dart`, `test/data/migration_test.dart`

**Schema v2** (`schemaVersion = 2`, `onUpgrade` from 1 adds columns/tables, keeps data):
- `meta`: `cloud_id text null`, `device_id text null`, `block_start int null`, `block_end int null`, `block_next int null`, `last_pull text null`.
- `entries`: `sync_state text default 'synced'` (`synced` | `pending`), `base_version int default 0` (server version this local edit started from).
- new `conflicts(entry_id pk, server_json text)`.

**Interfaces — Produces:**
- `abstract class EntryWriter { Future<List<Entry>> createEntries(List<EntryDraft> drafts, String observer); Future<Entry> updateEntry(String id, EntryDraft data, String observer); Future<void> deleteEntry(String id, String observer); }` — `LocalStore implements EntryWriter` (unchanged behaviour for local DBs).
- `LocalStore`: `String? get cloudId`; `Future<void> linkToCloud(String cloudId, String deviceId)`; `({int next, int end})? get block`; `Future<void> setBlock(int start, int end)`; `Future<List<Entry>> createEntriesFromBlock(List<EntryDraft>, String observer)` (pending; throws `NoNumbersLeft` when block can't cover all drafts, inserting none); `Future<void> insertSynced(List<Entry>)`; `Future<List<Entry>> pendingEntries()`; `Future<void> markSynced(String id, int version)`; `Future<bool> applyRemote(Entry server)` (replace if local not pending, returns false if local is pending); `Future<DateTime?> lastPull()` / `setLastPull(DateTime)`; `Future<void> addConflict(Entry server)`, `Future<List<(Entry mine, Entry server)>> conflicts()`, `Future<void> removeConflict(String id)`.
- `updateEntry`/`deleteEntry` on a cloud-linked store set `sync_state = 'pending'`; `base_version` keeps the last synced version.

### Task 3: SyncEngine against a fake cloud

**Files:** Create `lib/cloud/cloud_api.dart`, `lib/cloud/sync_engine.dart`, `test/support/fake_cloud_api.dart`; Test `test/cloud/sync_engine_test.dart`

**Interfaces — Produces:**
- `class CloudDb { final String id, name, role; }`
- `sealed class PushResult` → `PushOk(int version)`, `PushConflict(Entry server)`.
- `class CloudOffline implements Exception` — thrown by `CloudApi` for network failures (vs. `CloudDenied` for permission errors).
- `abstract class CloudApi { Future<List<CloudDb>> listDatabases(); Future<DatabaseDef> fetchDefinition(String db); Future<int> fetchNextNumber(String db); Future<void> createDatabase(DatabaseDef def, {required int nextNumber, List<Entry> rows = const []}); Future<void> updateDefinition(DatabaseDef def); Future<List<Entry>> createEntries(String db, List<EntryDraft> drafts, String observer); Future<({int start, int end})> reserveBlock(String db, String device, int size); Future<PushResult> pushEntry(String db, Entry e, {required int baseVersion}); Future<List<(Entry, DateTime)>> changesSince(String db, DateTime? since); Stream<void> remoteChanges(String db); Future<String?> myRole(String db); Future<List<({String email, String role})>> members(String db); Future<void> setMember(String db, String email, String role); Future<void> removeMember(String db, String email); }`
- `FakeCloudApi implements CloudApi` (test support): in-memory, `online` flag that makes every call throw `CloudOffline`, implements numbering/versions like the SQL.
- `enum Connection { online, offline }`; `class SyncStatus { Connection connection; int pending; int conflicts; }`
- `sealed class SyncEvent` → `WentOffline()`, `BackOnline(int synced)`.
- `class SyncEngine implements EntryWriter { SyncEngine(LocalStore store, CloudApi api, {int blockSize = 50}); ValueListenable<SyncStatus> get status; Stream<SyncEvent> get events; Future<void> start(); Future<void> syncNow(); Future<void> resolve(String entryId, {required bool keepMine}); Future<void> dispose(); }`

Behaviour:
- `createEntries`: online → `api.createEntries` → `store.insertSynced`; on `CloudOffline` → mark offline (emit `WentOffline` once) → `store.createEntriesFromBlock`.
- `syncNow`: refresh the definition (`fetchDefinition`; if it differs from `store.def` → `store.updateDefinition`, so Structure changes made elsewhere arrive), ensure block (reserve when none or `next > start + size/2`), push each pending (`PushOk` → `markSynced`; `PushConflict` → `addConflict`), pull `changesSince(lastPull)` → `applyRemote` (if refused because pending and server version > base_version → `addConflict`), `setLastPull`. Transition offline→online emits `BackOnline(n pushed)`.
- `start`: `syncNow`, subscribe `remoteChanges` → `syncNow`, `Timer.periodic(30 s)` → `syncNow`.
- `resolve(keepMine: true)` → push with `baseVersion = server.version`; `false` → `applyRemote(server)` forced.

- [ ] **Step 1: Failing tests** (fake cloud): online create gets server numbers `MAS-0001..`; offline create uses block numbers and emits one `WentOffline`; back online pushes pending and emits `BackOnline(2)`; block exhausted offline → `NoNumbersLeft` (Review Focus 1); two engines on one fake: A edits offline, B edits online, A reconnects → A has 1 conflict, server unchanged (Review Focus 2); `resolve(keepMine: true)` pushes A's version; pending survives engine restart (Review Focus 3).
